# SMS Spam Detector

A simple Streamlit web app that classifies an SMS message as **spam** or **not spam** using a Naive Bayes classifier.

## How it works

- Trained on the [SMS Spam Collection dataset](spam.csv) (5,572 labeled messages, 5,169 after removing exact duplicates).
- The data is split 80/20 (stratified) **before** vectorizing; the `CountVectorizer` (bag-of-words) is fitted on the training split only, so no test data leaks into training.
- Classified with a `MultinomialNB` model. On the held-out test set: accuracy ~98.7%, spam precision ~97.6%, spam recall ~91.6%, spam F1 ~94.5%. The notebook also prints the full classification report and confusion matrix.
- The model and the fitted vectorizer are pickled (`spam.pkl`, `vectorizer.pkl`) and loaded by the app for inference.

## Running locally

```bash
pip install -r requirements-dev.txt   # app + notebook (use requirements.txt for the app only)

# Train from scratch: creates spam.pkl and vectorizer.pkl
jupyter nbconvert --to notebook --execute --inplace "Spam Detector.ipynb"

# Start the app
streamlit run app.py
```

You can also open `Spam Detector.ipynb` in Jupyter and run all cells instead of the `nbconvert` command.

Enter a message in the text box and click **Predict** to see whether it's spam.

> The pickles must be loaded with the same scikit-learn version that created them (pinned in `requirements.txt`). If you change that version, re-run the notebook.

## Files

| File | Purpose |
|---|---|
| `app.py` | Streamlit app for inference |
| `Spam Detector.ipynb` | Training pipeline: cleans data, splits, trains, evaluates, and writes both pickles |
| `spam.csv` | Training dataset |
| `spam.pkl` | Pickled trained model (generated by the notebook) |
| `vectorizer.pkl` | Pickled fitted `CountVectorizer` (generated by the notebook) |
| `requirements.txt` | Runtime dependencies for the app (used for deployment) |
| `requirements-dev.txt` | App dependencies plus what the notebook needs |

## Deployment

Deployed on Streamlit Community Cloud with `app.py` as the entry point. The committed `spam.pkl` and `vectorizer.pkl` are loaded at startup, so no training happens on the server.
